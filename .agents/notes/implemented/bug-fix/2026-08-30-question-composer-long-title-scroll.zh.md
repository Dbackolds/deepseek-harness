# Agent Note: 长问题正文与选项一起滚动

Status: implemented

[English](2026-08-30-question-composer-long-title-scroll.md) | 中文

## 问题

提问卡片把高度限制在 `min(60vh, 520px)`，以便页脚操作留在屏幕内。问题正文当时放在 `flex-shrink: 0` 的页眉里。因此超长题干会在滚动区拿到高度之前就把限额吃完：选项列表和自定义答案行高度变成 0，`scrollHeight === clientHeight`，用户既滚不到选项，也无法选择。先前针对选项行收缩的修复对折行选项文案仍然成立；它覆盖不到从未进入滚动区的正文。

## 决策

展开卡片把问题正文当作 `[data-question-scroll]` 的滚动内容，与详情和选项列表放在一起。页眉只保留眉题以及收起、关闭操作。页脚的翻页器、跳过和提交留在滚动区外。

收起后的卡片仍在页眉条带里显示正文，以便识别尚未回答的问题。该正文限制为两行，因为收起会取消高度上限；不截断的题干会重新盖住收起本想露出的对话。

## 备选方案

**给页眉正文单独设置 `max-height` 和 `overflow-y: auto`。** 否决。选项仍在这个内层滚动器下面。题干一旦占满卡片限额，选项列表高度仍是 0；用户只能滚动正文，永远到不了答案。

**去掉卡片的 `max-height`，让超长题干自行增高。** 否决。编辑器座位是固定高度、`overflow: hidden` 的对话列。不限高的卡片会把自己的提交按钮挤出可视区，而这正是限额要防止的失败。

**在展开态截断正文。** 否决。题干就是用户正在回答的决策。截断只属于收起条带，那里的正文是提醒，不是阅读面。

## 测试

组件 spec 要求标题和选项行共享 `[data-question-scroll]`，跳过操作留在该区域外，并覆盖收起/展开循环。组装后的 `question-composer` Web e2e 通过真实的 user-questions seam 在限高视口里提出折行题干，并要求选项行有正高度、正文区域可滚动、跳过按钮仍在卡片内；随后滚到选项并提交。

## 后果

超长题干不再挡住答案。短问题会把正文移到页眉操作下方的下一行，因此收起和关闭控件留在紧凑条带上，而不是贴在折行标题旁边。收起后的卡片最多显示两行题干。
