# Agent Note: Models 设置卡片默认收起

Status: implemented

[English](2026-08-15-models-setup-card-collapsed-by-default.md) | 中文

## 问题

首次运行时，DeepSeek、FAC 这类组合拥有的提供方会在打开「设置 → 模型」时直接展开完整的 API 密钥表单。两张卡片加上底部的添加操作会在用户选定提供方之前占满面板；只想配一把密钥的用户也必须先略过另一张表单。

## 决策

首次运行的设置卡片在用户点取消或成功保存并变成行之前，仍是该提供方在页面上的存在形式。表单默认收起。卡片标题是原生 `<details>` / `<summary>` 折叠控件：展开后露出原先整卡所用的同一个 `ProviderEditor`，再次收起时编辑器保持挂载，因此已键入的密钥不会丢失。标题由折叠控件持有，编辑器隐藏自己的标题。取消与保存留在展开后的表单体里。

普通行、添加卡片和自定义提供方卡片不变。关闭一张设置卡片仍然只关掉这一张。

## 考虑过的替代方案

**改用行上的「编辑」并取消设置卡片姿态。** 不采用：首次运行仍需要这张卡片在用户关掉它之前代表该提供方；收起表单即可保留这一姿态，而不把密钥字段强行铺在页面上。

**收起时卸载编辑器。** 不采用：用户收起卡片去对比提供方时，已键入的密钥会消失。

**第一张设置卡片默认展开、其余收起。** 不采用：页面无法知道用户打算配置哪一个组合拥有的提供方。

## 后果

在尚无密钥的首次运行配置下打开模型页时，DeepSeek 与 FAC 显示为带标题的收起卡片。只有展开标题才能到达该卡的密钥字段。已收起的草稿会保留到取消、保存或离开页面。

## 测试

包测试钉住首次运行的收起渲染、收起后再展开时草稿仍在、展开后只写存储密钥，以及取消仍然只关掉该卡。模型页空态 ARIA 快照钉住添加流程旁收起的 FAC 卡片。可用提供方 e2e 会先展开 FAC，再验证在打开的添加卡片旁取消该卡。
