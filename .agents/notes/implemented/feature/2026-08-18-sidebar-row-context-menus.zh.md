# Agent Note: 侧边栏行右键菜单

Status: implemented

[English](2026-08-18-sidebar-row-context-menus.md) | 中文

## Problem

侧边栏历史列表里的 Workspace 行和 Session 行已经通过悬停才出现的行尾省略号提供重命名、分叉、归档、添加文件夹和删除。打开这些操作需要找到一枚平时隐藏的 16px 控件。在行上右键是列表行的惯用手势，但目前没有反应，于是浏览器的页面菜单会盖在历史列表上。

省略号下拉锚定在触发按钮上，并在指针离开时关闭。右键必须开在指针处，并一直开到选中、点到外面或按 Escape。两套手势共用一个 `Menu` 实例，会把打开状态、定位和移出即关绑在一起。

## Decision

真实 Workspace 行和非空白 Session 行各自持有两个 `Menu` 实例。行尾省略号仍在悬停才显示的 `rowActions` 单元格里：测量触发按钮、指针离开即关，悬停用户的行为不变。右键菜单是第二份 portal 列表，渲染在该隐藏单元格之外，并用 `clientX`/`clientY` 处的零尺寸矩形定位。打开其中一个会关掉另一个。两份列表通过每种行各自的共享选择函数提供同一组操作——Workspace 为重命名／添加文件夹／移除文件夹／删除工作区，Session 为重命名／分叉会话／归档会话。任一菜单打开期间仍抑制悬停卡片。当前 GUI 提供的是 `lib/client.js` 而不是源码；`/reboot` 只重启会话，不会重建或替换该 bundle。

Ungrouped 分组和空白「新会话」行仍然没有这些操作。它们的右键只调用 `preventDefault`，避免浏览器菜单盖住列表。

## Alternatives considered

**共用一个 `Menu`，在省略号和指针之间切换锚点。** 否决：两套手势在定位和移出即关上不一致，一个实例无法同时保住两边的行为。

**把右键菜单做成树外的侧边栏插件。** 否决：这些动词和对话框已经住在 `ui-workspace`；插件要么重做一遍，要么穿过 slot 约定去改名、分叉、归档和删除。

**给右键菜单另一套与省略号不同的条目。** 本次否决：缺的是打开入口，不是新的动词集合。

**没有动词的行继续弹出浏览器原生菜单。** 否决：在 Ungrouped 或空白「新会话」上右键仍会用与该行无关的页面级条目盖住历史列表。

## Consequences

每条合格行有两个菜单实例、一份条目。指针定位复用已有的 portal `getAnchorRect` 席位；`Menu` 本身不增加右键模式。搜索结果行仍没有行菜单，因此那里的右键仍是浏览器菜单。

## Testing

`rows.client.spec.tsx` 在已知指针位置用右键打开右键菜单，再打开省略号菜单，并断言那是另一个实例、另一处定位。它从省略号路径派发重命名，保留原有省略号用例，并断言 Ungrouped 与空白「新会话」行会拦截浏览器菜单且不渲染条目。
