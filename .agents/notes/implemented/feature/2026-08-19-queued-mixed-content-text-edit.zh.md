# Agent Note: 编辑混合内容排队消息的文本

Status: implemented

[English](2026-08-19-queued-mixed-content-text-edit.md) | 中文

## 问题

Web QueueDock 已经能就地编辑普通会话中仍待处理的入队项。同时带有已准入图片的行却被当作不可编辑：客户端把 `text` 投影为 `null`、禁用编辑控件，而 `session.updateQueue` 会用编辑载荷整段替换内容。保存该载荷会丢掉图片，因此混合内容行只能删除或插话发送。

用户仍需要在驱动器认领之前改排队图片消息的说明文字。从 composer 再入队无法寻址该入队项；先删再发可能打乱 FIFO，或丢掉已经准入的附件。

## 决策

`session.updateQueue` 的编辑只接受恰好一个文本块。宿主用该文本替换原有全部文本块，并按原顺序保留已准入的非文本块（包括图片）。仅含图片的项会在末尾追加一个文本块。空载荷或含非文本块的载荷仍返回 `attachment-error`，原因为 `QUEUE_EDIT_NON_TEXT`，因此编辑路径无法绕过提示词准入注入新图片。

客户端队列投影会把现有文本块拼接为每行的 `text`。QueueDock 对混合内容行启用同一个内联编辑器，并且仍然只发送一个文本块。下一份权威 `session/queue` 快照才是可见提交。已寻址 subagent 行保持只读。

## 备选方案

**继续让混合内容行只读。** 否决：用户已经能删除或插话该入队项；拒绝改说明文字会迫使用户先删再发，从而打乱 FIFO 或丢掉已准入图片。

**由浏览器发送完整的混合内容。** 否决：队列编辑器是单个文本框，浏览器不得重新准入或重建持久图片块。这些块已经由宿主拥有。

**在 QueueDock 中再做一个图片编辑界面。** 否决：本次请求是改排队文本，不是增删或替换附件。

## 后果

排队图片在说明文字变更后仍保留已准入附件。原先多个文本块会折叠为位于第一个文本位置的一个块。清空说明文字仍不能保存，因为编辑器继续要求非空白文本，这与现有纯文本保存规则一致。

## 测试

Host proxy 测试固定混合内容编辑会保留图片、仅图片编辑会追加文本，以及非文本载荷仍返回 `QUEUE_EDIT_NON_TEXT`。运行时投影测试固定混合内容的 `text` 为拼接后的说明文字。QueueDock 测试固定混合内容行的编辑控件可用，且保存时只发送一个文本块。
